# Ecosystem Reconstitution Architecture

## Preserve

`ggen` remains the semantic manufacturing kernel. `ggen-legacy` remains the executable corpus and reconstitution foundry. Each product repository remains an independent authority domain with its own doctrine, validation ladder, release boundary, and receipts.

## Fence

This program reconstructs repository object graphs. It does not assert semantic equivalence among repositories and does not combine their trees into one monorepo.

The selected source object for a repository may be:

- an integrated merge consequence;
- an integrated branch consequence;
- an active candidate head;
- a closed-unmerged preserved candidate;
- a transport-only lineage object.

These dispositions cannot be substituted for one another.

## Reconstruction layers

1. **Kernel and corpus:** `ggen`, `ggen-legacy`.
2. **Evidence and compatibility:** `wasm4pm`, `wasm4pm-compat`, `chicago-tdd-tools`, `lsp-max`, `unrdf`.
3. **Planning and agent runtimes:** `mfw`, `ferroplan`, `ostar`.
4. **Product and application realizations:** `open-ontologies`, `zoela`, `truex`, `praxis`, `dspygen`, `stpnt`, `clap-noun-verb`.
5. **Specification projection:** `agile-protocol-specification`.
6. **Transport lineage:** `clnrm`, excluded from product authority.

The executable dependency graph in the manifest, not this prose grouping, owns reconstruction order.

## Receipt chain

The authored manifest is observation. The verifier emits a deterministic plan. The exact-source witness crosses real Git and filesystem boundaries and records:

- requested commit;
- observed commit;
- Git tree;
- tracked-path count;
- doctrine files present;
- source disposition;
- product/transport boundary;
- BLAKE3 receipt digest;
- unexecuted repository validation obligations.

The source receipt does not promote repository standing. A successful fetch proves only that the exact source object can be reconstituted into a clean tree.

## Falsifier

The program is falsified if it accepts an omitted repository, duplicate identity, malformed source SHA, unknown dependency, dependency cycle, inconsistent PR disposition, promoted transport, direct actuation, canonical source outside the admitted source set, missing source receipt, or duplicate source receipt.

## Extension

After exact source retrieval, a later controller-owned foundry checkpoint may consume these authored inputs and receipts to manufacture lineage, catalogs, solution-pack declarations, migrations, and workstream admission reports. That controller run must preserve the repository-owned validation commands and standing ceilings in this corpus.
