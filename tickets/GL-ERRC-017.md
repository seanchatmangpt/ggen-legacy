## Outcome

`authority/project-001-promotion.json`'s `bounded_rails` names four rails
with `"standing": "ALIVE"`, each citing an `evidence` array of files this
session independently re-checked with `test -e` against the real working
tree. Five of the ten total cited paths do not exist on disk:
`docs/book/index.html`, `docs/book/print.html`,
`ggen-legacy-verifier-v26.8.1.tar.gz`,
`ggen-legacy-verifier-v26.8.1.receipt.json`, and
`evidence/foundry-runtime-candidate.json`. The `foundry_runtime_candidate`
rail is the most severe case: its `evidence` array names exactly one file
(`evidence/foundry-runtime-candidate.json`), that file does not exist, and
it has zero other cited evidence — meaning that rail's `"standing":
"ALIVE"` claim has, by this file's own citation mechanism, no locatable
backing whatsoever, not partial backing. The other three rails
(`documentation_and_authority`, `verifier_appliance_reference`,
`offline_application_transport`) are mixed: each has at least one existing
evidence file alongside at least one missing one. This ticket does not
manufacture the missing evidence files (that would launder an unverified
build artifact into a checked-in claim of the exact kind
`no-overclaiming` discipline forbids) and does not delete the rails outright
(the existing evidence files that do check out may still support a real,
narrower claim). It reduces each rail's standing to reflect only what its
still-locatable evidence actually supports: `foundry_runtime_candidate`
drops from `ALIVE` to `UNVERIFIED` (zero locatable evidence, full stop);
the three mixed rails drop from `ALIVE` to `PARTIAL_ALIVE` with an added
`missing_evidence` array listing exactly which cited paths do not resolve,
so a future session's `test -e` recheck of the same claim starts from an
honest baseline instead of an overclaimed one — mirroring
`docs/v26.8.20/ultracode-loop-progress.md`'s item-12 checklist finding
(**correction, per `tickets/AUDIT-REPORT.md`'s check-4 finding**: this file
previously mis-cited `docs/v26.8.20/DECISIONS.md`, which has no item-12
section — the real item-12 finding lives in the progress-checklist file,
not `DECISIONS.md`), which flagged this but
did not act on it pending repo-owner confirmation this is a real gap rather
than an untracked build-artifact situation. Since this session reconfirmed
the exact same 5-of-10 gap independently (same files, same missing set),
the reduction is warranted regardless of that open question — an
`ALIVE` standing citing a nonexistent sole evidence file is wrong either
way, whether the eventual fix is "regenerate the artifact" or "the claim
was always too strong."

## Hard laws

1. `foundry_runtime_candidate.standing` becomes `"UNVERIFIED"`, not
   `"REFUSED"` or silently left `"ALIVE"` — the rail's own `scope` text
   ("exact candidate verification only") may still be true, this ticket
   only asserts the *evidence for it* is not currently locatable, which is
   a narrower and more defensible claim than either extreme.
2. Every rail whose standing is reduced gains a `missing_evidence` array
   (sibling key to the existing `evidence` array) listing the exact
   relative paths this ticket confirmed absent via `test -e` — not a
   prose description, the literal path strings, so a future session can
   `test -e` each one mechanically without re-deriving which paths were
   meant.
3. No rail's standing is *raised* by this ticket — this is a strict
   narrowing pass; if re-verification during execution finds a cited path
   actually does exist (e.g. this session's check was run from the wrong
   directory), that path is removed from `missing_evidence`, not treated as
   license to also strengthen an unrelated claim.
4. `project_standing` (currently `"PARTIAL_ALIVE"` at the top level) is
   re-derived consistently with whatever the four rail-level standings
   become — if this ticket's execution finds the top-level field's stated
   logic (undocumented in the file itself) does not compose cleanly from
   the four rails, that composition ambiguity is flagged in the ticket's
   own follow-up, not silently resolved either direction.
