# Roadmap, Glossary, and FAQ

## Implementation roadmap

### Phase 0 — Project 001

Close product, architecture, governance, schema, fixture, verifier, security, operations, and procurement authority.

### Phase 1 — Exact-source observation

Implement exact repository resolution, read-only Git/tree observation, provenance, and observer receipts.

### Phase 2 — Capability admission

Implement capability identity, SHACL/policy admission, contradiction refusal, and disposition ledger.

### Phase 3 — Manufacture

Implement bounded candidate lattices, GBB/bblock/pack/profile composition, deterministic projectors, and atomic local broker.

### Phase 4 — Equivalence

Implement positive witnesses, refusal fixtures, and observable-contract comparison.

### Phase 5 — Evidence

Implement receipt codecs, OCEL evidence, integrity verification, and immutable storage.

### Phase 6 — Replay and crown

Implement clean-room replay, external verifier report, bootstrap crown, Release Admission, and real predecessor Sunset Admission.

### Phase 7 — External pilot

Perform Repository Observation on a bounded external repository before attempting full retirement.

Each phase ends at a Gall checkpoint with a typed state. Calendar completion cannot erase an earlier blocker.

## Glossary

**Admission:** decision that an observation may become authority.  
**Authority:** semantic source of lawful consequences.  
**Capability:** bounded observable behavior with identity and provenance.  
**Combinatorial maximalism:** maximum reversible lawful construction before bounded actuation.  
**Equivalence case:** executable comparison over a declared observable contract.  
**GBB:** canonical semantic Building Block.  
**Pack:** immutable capability distribution with contract, verifier, and receipt.  
**Receipt:** evidence binding consequence to exact inputs and coordinate.  
**Replay:** re-execution from the same admitted coordinate.  
**Release Admission:** decision that a replacement may release.  
**Standing:** bounded evidence state assigned by a verifier.  
**Sunset Admission:** decision that a predecessor may retire.

## FAQ

### Is this a rewrite tool?

No. Rewriting may occur, but the product owns archaeology, authority, disposition, equivalence, verification, replay, and retirement.

### Must the legacy repository build?

No for observation. A broken build constrains execution evidence and remains explicit.

### Does it prove arbitrary programs equivalent?

No. It proves equivalence over an admitted observable contract.

### Can the result refuse retirement?

Yes. A correct `BLOCKED` or `PARTIAL_ALIVE` result is more valuable than unsupported success.

### Is the product autonomous?

It may automate observation, planning, construction, and verification. Consequential DO remains brokered and standing remains independent.

### What is current v26.8.1 standing?

The documentation and authority bootstrap is the active Project 001 deliverable. Product implementation and external production standing remain `UNKNOWN` until exact-head execution evidence exists.
