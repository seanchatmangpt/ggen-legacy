# Working Backwards Press Release — ggen-legacy v26.8.1

## ggen-legacy Makes Legacy Repository Retirement Provable

### Verified Repository Reconstitution reconstructs undocumented behavior, manufactures a replacement from machine-readable authority, and independently determines whether the predecessor can be retired

**PASADENA, California — Future launch date** — ggen today announced ggen-legacy v26.8.1, the first productized implementation target for Verified Repository Reconstitution.

ggen-legacy is designed for enterprises that can produce replacement code but cannot prove that the replacement preserves the real behavioral contract of the legacy repository. The product observes repository history and operating evidence, admits capabilities into semantic authority, assigns every capability a disposition, manufactures governed replacement surfaces, verifies positive and refusal behavior, replays the manufacture, and computes Release Admission and Sunset Admission.

Traditional modernization ends at deployment. ggen-legacy changes the completion condition. A project closes only when capabilities, owners, equivalence cases, verifiers, evidence, receipts, and replay are complete—or when the system returns a typed blocker instead of a success claim.

Customers receive a Repository Archaeology Graph, Legacy Capability Ledger, Manufacturing Authority, Manufactured Replacement Repository, Equivalence Evidence Portfolio, Repository Standing Report, Deterministic Rebuild Receipt, and Sunset Admission decision.

> “Legacy replacement should not end when the new code ships. It ends when the complete contract is accounted for, the replacement is independently verified, replay matches, and the old implementation has a defensible retirement decision.” — Sean Chatman

The v26.8.1 Project 001 corpus establishes the enterprise product, architecture, security, operations, procurement, and evidence authority. Production implementation and external standing remain governed by exact-head execution evidence.
